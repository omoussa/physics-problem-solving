# Contributing

Keep each skill self-contained. Required instructions, references, icons, and scripts belong inside that skill's directory. Preserve the defined scope and numbered solution structure unless the repository owner deliberately approves a scope change.

For a correction, include a minimal problem statement, the observed output, the expected physics or formatting, and the affected skill. Use invented examples rather than student records.

Verify signs, coordinate definitions, vector notation, symbolic algebra, units, precision, and physical assumptions. Add or update an acceptance problem when it captures a meaningful behavior change. If the diagram renderer changes, render and visually inspect a representative force diagram.

Keep the portable and compatibility manifests synchronized in name, version, license, and presentation. Record changes in `CHANGELOG.md`. Generate future release archives from these source folders rather than maintaining separate copies of skills. Include the MIT license in every individual-skill distribution.

Do not publish a verified-installation claim until the relevant host installation and acceptance checks have actually passed.
